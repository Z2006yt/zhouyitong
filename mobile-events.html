实测规律：touchstart → 若干次 touchmove → touchend → 最后才是 click。 移动距离越大、持续时间越长，touchmove 的次数越多，这就是“跟手”的原理。
小心“执行两次”：touchend 之后系统还会补发一次 click。如果两套逻辑都写，就会点一次执行两次；要么二选一，要么在触摸处理里 preventDefault()。
操作实测事件顺序关键观察
单击touchstart → touchend → click没有 touchmove，手指几乎没有位移
向上拖动touchstart → touchmove × N → touchend → clickN 随拖动距离增大，约每帧一次（≈60 次/秒）
向左快速滑touchstart → touchmove × N → touchend → click速度越快 N 越少，但单次位移更大
双指触摸touchstart（touches=2）→ touchmove（touches=2）… → touchend（2→1→0）双指时 touches.length 为 2，抬手时要从 changedTouches 取坐标
长按后抬起touchstart →（约 600ms 无事件）→ touchend → click长按期间没有 touchmove，除非手指有抖动

验收三问能讲清，比写得出更重要

一次拖动里 touchmove 大约触发多少次？和距离什么关系？
约每帧一次，即 60 次/秒左右；在速度不变时，拖动距离越大、持续时间越长，触发次数就越多。所以次数描述的是“过程长短”，位移描述的是“走了多远”，两者不是一回事。

click 出现在 touchend 之前还是之后？
之后。touchend 先结束触摸，浏览器随后补发 click；历史上还会等约 300ms 判断是不是双击，所以移动端点击会“慢半拍”。

如果把 touchend 换成 touchcancel，会发生什么？
正常抬手不会触发 touchcancel，它只在被系统打断（来电、通知横幅、手势返回）时出现。替换后正常滑动收不了尾，状态会卡住。正确做法：touchend 负责正常收尾，touchcancel 负责清理定时器与临时状态，两个都监听。
